# Findings

This document records repository-level findings that matter when changing the
application. Resolved items describe the current safeguards, while open items
describe operational constraints rather than customer-facing behavior.

## Resolved safeguards

| Area                     | Current safeguard                                                                                                                                                                                                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Sitemap freshness        | Product mutations revalidate the sitemap tag and relevant public routes.                                                                                                                                                                                                                   |
| WhatsApp return link     | The thank-you page accepts only a valid `https://wa.me/` link.                                                                                                                                                                                                                             |
| R2 cleanup               | Product image deletion removes unreferenced keys after the database transaction commits. Shared keys survive until their final reference is gone.                                                                                                                                          |
| Note and brand freshness | Related public pages are revalidated after translation or display-name changes.                                                                                                                                                                                                            |
| Action envelopes         | Admin actions use shared `ActionResult<T>` and `fieldErrors()`. Raw Spanish fields remain at the client boundary.                                                                                                                                                                          |
| Cart compatibility       | Carts persist under the `parfam-cart` localStorage key (zustand `persist`, version 0); carts stored under the earlier key were discarded.                                                                                                                                                  |
| Public action safety     | Checkout uses a honeypot, request validation, price rereads, and rate limiting.                                                                                                                                                                                                            |
| Product safety           | Publication checks, relationship ID validation, product ownership checks, and R2 key validation run server-side.                                                                                                                                                                           |
| Security headers         | `next.config.ts`'s `headers()` sends CSP, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, and `Permissions-Policy` on every route; see "Security headers" in `docs/integrations.md`.                                                                                       |
| R2 bucket isolation      | Dev uses its own bucket (`parfam-mdq-imagenes-dev`) with its own R2 token and CORS; production uses `parfam-mdq-imagenes` with its own token and CORS. A dev token cannot write to production's bucket, so R2 cleanup can safely scope to one database's keys; see `docs/integrations.md`. |

## Open operational considerations

| Topic                            | Current behavior                                                                                                                                                                                                                                                                                                                                                                 | Follow-up when needed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rate limiting                    | `src/lib/rate-limit.ts` is in-memory and process-local.                                                                                                                                                                                                                                                                                                                          | Move counters to shared storage before horizontal scaling.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Catalog sorting                  | `listCatalog` (`src/lib/store/catalog-listing.ts`) still sorts in memory, since price sort needs the minimum active variant price, an aggregation Prisma's `orderBy` cannot express. It loads a light row (id, name, timestamps, active variant prices) for every match instead of the full card shape, then re-queries only the current page's ids for the returned cards.      | Move ordering fully to SQL (e.g. a raw query or a materialized minimum price column) if data volume requires it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Background cleanup               | R2 cleanup is best effort after database writes.                                                                                                                                                                                                                                                                                                                                 | Add reconciliation tooling if orphaned object cost becomes material.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Test coverage                    | Integration tests cover the reference importer, translation coverage, and adoption read model; E2E covers store, checkout, and admin security. Image type/trim helpers have no automated coverage.                                                                                                                                                                               | Add focused integration/e2e coverage for image helpers when they change.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| CI validation                    | `.github/workflows/ci.yml`'s `checks` job runs typecheck, lint, and tests on every pull request (required to merge); the `deploy` workflow's `publish` job builds and publishes the image.                                                                                                                                                                                       | None.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| "Se parece a" invalidation scope | `revalidateStore` in `src/app/admin/(panel)/productos/actions.ts` calls `revalidateTag(TAG_SIMILAR_PRODUCTS, "max")`, which marks the shared cached ranking stale for every product, but only calls `revalidatePath` for the edited product's own `/producto/[slug]` page. Other products whose "Se parece a" list could have shifted are not individually revalidated as pages. | Intentional. Product pages call `getSiteSettings()`, which calls `connection()` in `src/lib/settings.ts`, so they render dynamically and are never served from the cache Next keeps for statically rendered pages. The only staleness is the tagged data cache: with `"max"`, `revalidateTag` uses stale-while-revalidate, so the first request to another product's page after the edit can still recompute from the (now stale-marked) similar-products cache entry while Next revalidates it in the background; the next request gets the refreshed ranking. No page goes permanently stale without a visit, and enumerating every other product's `/producto/[slug]` path on each edit would be expensive for no lasting benefit. |

## Deferred refactoring findings

These were found during a cleanup refactor and deferred because fixing them
changes behavior or touches the price, order, or image-write paths, which have
no automated test coverage.

| Topic                                    | Current behavior                                                                                                                                                                                                                                                                                                                                     | Why it is deferred                                                                                                                                                                                              |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Order price read outside the transaction | `createOrder` in `src/app/(store)/checkout/actions.ts` reads `ProductVariant` prices through `resolveCartLines` (`src/lib/store/server-cart.ts`) before opening `prisma.$transaction`; the transaction only takes the order-number sequence and creates the `Order`/`OrderItem` rows.                                                                | A price change between that read and the create still persists the earlier price in the `OrderItem` snapshot. Fixing it touches the price and order-write path.                                                 |
| In-flight dedup in cart reconciliation   | `useCartReconciliation` (`src/lib/store/use-cart-reconciliation.ts`) keeps a module-level `inFlightValidation` dedup because the presentational `CartItemList` it runs inside (`src/components/store/cart/cart-item-list.tsx`) mounts in both `cart-drawer.tsx` and `carrito/_components/cart-content.tsx`, so it can run twice at once.             | Removing the dedup changes when the drawer reconciles with the database, a behavior change.                                                                                                                     |
| Duplicated sync algorithm                | `syncVariants` and `syncImages` in `src/app/admin/(panel)/productos/product-persistence.ts` both implement the same algorithm: collect kept IDs, `deleteMany` the rest, then update or create rows by index.                                                                                                                                         | An off-by-one there corrupts product variants or images, and the image-write path has no automated coverage.                                                                                                    |
| Single-use `react-dropzone`              | `src/app/admin/(panel)/productos/_components/image-panel.tsx` is the only place that imports `react-dropzone`'s `useDropzone`, for accept/maxSize/drag state.                                                                                                                                                                                        | Low value: it reimplements working UX, and the server already validates upload type and size.                                                                                                                   |
| Per-route Open Graph image files         | Eight `opengraph-image.tsx` files under `src/app/(store)/` (`checkout`, `como-comprar`, `carrito`, `presentaciones`, `concentraciones`, `contacto`, `producto/[slug]`, `pedido/[number]/gracias`) re-export the single image generated in `src/app/(store)/opengraph-image.tsx`, since Next's file convention does not inherit into nested segments. | The failure mode is silent (WhatsApp link previews). `src/lib/seo.ts` also documents intentionally not setting `openGraph.images`, so collapsing the duplication needs a design decision, not a mechanical fix. |
| Eyebrow label typography                 | Small uppercase labels use several font sizes and tracking values.                                                                                                                                                                                                                                                                                   | Normalizing them changes rendered pixels; see `design-system/parfam-mdq/MASTER.md` (finding B-08) for detail.                                                                                                   |

## Presentation-only price arithmetic

Checkout and cart components use `Number()` for display totals through
`lineSubtotal` and `cartSubtotal` in `src/lib/cart.ts`, used by
`src/app/(store)/checkout/_components/checkout-form.tsx`
(mobile total), `src/components/store/cart/cart-summary.tsx`,
`cart-total-announcer.tsx`, and `cart-item-row.tsx`. This is an intentional
presentation exception to the Decimal rule. Prices still cross to the client
as strings, writing actions reread prices from the database, and persisted
order totals use `Prisma.Decimal` on the server.

## Refactoring constraints

Historical Prisma migrations, Spanish public routes, query keys, raw action
payloads, localStorage keys, R2 prefixes, WhatsApp placeholders, and
environment variables are external or persisted contracts. Keep them stable, or
introduce an explicit migration or adapter.

The code is the authoritative source. Refresh this document whenever an
implementation change invalidates one of these statements.
